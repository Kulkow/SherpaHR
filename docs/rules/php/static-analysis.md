# Статический анализ PHPStan

Фиксируем **PHPStan level 9** в `backend/phpstan.neon`. Анализируем код, точку входа и тесты. PHPStan и PHPUnit подключаем через Composer как зависимости разработки, версии фиксируем в lock-файле. Level 9 включает строгую проверку операций над явно объявленным `mixed`. [Уровни PHPStan](https://phpstan.org/user-guide/rule-levels).

```neon
parameters:
    level: 9
    paths:
        - src
        - tests
        - router.php
```

- Сужаем типы входного JSON и результата PDO проверками до передачи в прикладной или доменный код. Обрабатываем `null` и `false` там, где они допустимы по контракту зависимости.
- Для массивов задаём тип элементов и обязательные ключи через PHPDoc. Аннотации должны совпадать с фактической валидацией. Для значений статуса и допустимых исходов используем подходящие нативные типы или enum.
- Исправляем причину предупреждения в типах, проверках или коде. Если при первом подключении потребуется baseline для старого кода, фиксируем его отдельно и сокращаем по мере исправления. Новые ошибки должны останавливать проверку.
- Используем одну конфигурацию и PHP 8.4 в Docker для локального запуска, pre-commit и CI. Целевая команда из корня проекта:

```bash
docker compose run --rm php-check vendor/bin/phpstan analyse --configuration=phpstan.neon
```
