# Упрощённый DDD и SOLID

## Где находятся правила

| Участок | Ответственность |
|---|---|
| HTTP-граница | Разобрать запрос, проверить форму и типы, передать данные в Use Case. Преобразовать результат или ошибку в согласованный JSON и HTTP-статус |
| Use Case | Организовать последовательность действий, проверить членство и архив, получить нужные агрегаты, вызвать доменную операцию и определить транзакцию |
| Домен | Защищать инварианты при создании и изменении. Примеры — пустое название, допустимость перехода статуса по согласованной матрице, неизменность автора комментария |
| Репозиторий | Загрузить и сохранить агрегат через PDO. Обеспечить атомарную проверку версии при обновлении |
| Запрос чтения | Собрать данные для списка, карточки или обзора с соблюдением условий доступа |

Сущность определяется идентификатором, объект-значение — своим содержимым, агрегат — границей согласованности записи. Для простого значения достаточно типизированного поля или enum. Отдельный класс нужен, когда он выражает самостоятельное правило или позволяет применить его единообразно. Контекст выделяем по различию языка, правил и ответственности за данные. [Сущности и агрегаты](../../ddd/entity-vo/README.md), [репозитории](../../ddd/repositories/README.md), [текущие сценарии](../../ddd/useCase/README.md).

## Как применять SOLID

- **S — одна ответственность.** Правило перехода статуса меняется в домене, а формат ответа — на HTTP-границе. Выделяем код, когда это упрощает поиск и проверку правила.
- **O — расширяемость.** Выносим изменяемое правило в именованную операцию, когда оно начинает применяться в нескольких сценариях. Для небольшой конечной матрицы переходов достаточно явной структуры и тестов.
- **L — подстановка.** При нескольких реализациях соблюдаем одинаковые условия входа, результат и обработку ошибок. Например, реализация репозитория сохраняет семантику конфликта версии.
- **I — узкие контракты.** Метод или интерфейс описывает нужную операцию. Чтение обзора и запись агрегата имеют разные входы и результаты.
- **D — направление зависимостей.** Домен работает с предметными данными без зависимости от PDO и HTTP. Прикладной код получает зависимости явно. Конкретный класс подходит, пока его контракт достаточен и отдельная реализация действительно не нужна.
