# Стиль и форматирование

За основу берём PSR-1, PSR-4 для автозагрузки и актуальный PER Coding Style для форматирования. PER развивает и заменяет PSR-12, сохраняя общий стиль и уточняя формат новых конструкций PHP. [PSR-1](https://www.php-fig.org/psr/psr-1/), [PSR-4](https://www.php-fig.org/psr/psr-4/), [PER Coding Style](https://www.php-fig.org/per/coding-style/).

- PHP-файлы в UTF-8 без BOM, окончания строк LF и один завершающий перевод строки. В файлах только с PHP закрывающий тег опускаем.
- Отступ — четыре пробела. Одна инструкция на строку. Строки длиннее 120 символов стараться переносить по смыслу. В многострочных списках аргументов и массивах ставить завершающую запятую.
- Пространство имён соответствует пути Composer с точным регистром. Классы, интерфейсы и enum именуем в PascalCase, методы и переменные — в camelCase, константы классов — в UPPER_SNAKE_CASE. Имена JSON-полей сохраняем по контракту API.
- Имя метода отражает действие и результат. Например, `hasMember()` возвращает `bool`, `findTask()` допускает отсутствие записи, а `assertProjectIsWritable()` сигнализирует о нарушении правила исключением. В коде используем термины [словаря проекта](../../architecture/domain-and-contracts.md).
- Включаем `declare(strict_types=1);` в PHP-файлах приложения и тестов. Типизируем свойства, аргументы и результаты. Для коллекций и структур JSON/PDO уточняем форму через PHPDoc, когда нативного типа недостаточно.
- Комментарии объясняют правило, причину выбора или ограничение. Для длинного SQL форматируем запрос и даём параметрам имена по смыслу. SQL-параметры и поля DTO должны однозначно соотноситься при ревью.
