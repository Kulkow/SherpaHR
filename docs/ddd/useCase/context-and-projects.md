# Контекст и проекты

## UC-01 · Выбрать демо-пользователя и увидеть проекты

**Актор:** пользователь локального демо. **Триггер:** открытие приложения или выбор другой персоны.

1. Angular по умолчанию выбирает Анну. При смене персоны интерфейс очищает предыдущий контекст, список проектов, задачи и карточку.
2. Интерфейс параллельно запрашивает `GET /api/context` и `GET /api/projects` с выбранным `X-Demo-User`.
3. Контекст возвращает текущего пользователя, каталог демо-пользователей, текущее серверное время UTC и время инициализации базы. Список проектов возвращает только проекты по членству, включая архив, с составом и счётчиком задач. Активные проекты идут перед архивными, внутри групп — по ID.
4. При загрузке интерфейс сохраняет выбранный проект, если он есть в новом списке. Иначе выбирает первый и переходит к [UC-02](task-reading.md). Если проектов нет и выбранный проект отсутствует, показывает пустое состояние.

**Альтернативы:** неизвестная персона даёт 401. При ошибке загрузки без выбранного проекта видна кнопка повтора. Данные SQLite этим сценарием не меняются.

## TECH-01 · Проверить готовность приложения

**Актор:** Docker Compose или разработчик. **Триггер:** запрос `GET /api/health`.

1. Маршрутизатор открывает SQLite и выполняет существующую инициализацию, если демо-база ещё не подготовлена.
2. API до проверки демо-пользователя возвращает 200 с `{"data":{"status":"ok"}}`.
3. Docker Compose проверяет значение `data.status`. При недоступности ответа или ошибке эта попытка healthcheck считается неуспешной.

Источники: [router.php](../../../backend/router.php), [ContextController.php](../../../backend/src/Http/ContextController.php), [app.ts](../../../frontend/src/app.ts#L36-L87), [Compose](../../../compose.yaml).
