# Агрегаты и границы записи

Агрегат задаёт границу согласованности при записи. В предлагаемой модели корни ссылаются друг на друга по идентификаторам. Чтение карточки может собрать данные из нескольких агрегатов.

| Агрегат и корень | Состав | Правила согласованности и граница записи |
|---|---|---|
| Пользователь (`User`) | Пользователь | Сохраняет идентичность пользователя. Общего обновления профиля и всех задач или комментариев автора не требуется. Демо создаёт пользователя при инициализации |
| Проект (`Project`) | Проект и его записи `ProjectMember` | Членство уникально в пределах проекта. Архив сохраняет историю, запись задач и комментариев запрещена. `owner_id` обозначает руководителя, членство проверяется отдельно. Если появится редактирование состава, правила совместного изменения владельца и участников нужно согласовать |
| Задача (`Task`) | Одна задача | Сохраняются принадлежность проекту, допустимые значения полей и версия. При создании и назначении проверяется членство исполнителя, если он задан. Изменение выполняется с условием по ожидаемой версии. Набор задач проекта может читаться без загрузки всех агрегатов в память |
| Комментарий (`Comment`) | Одна запись обсуждения | При добавлении прикладная операция проверяет принадлежность задачи доступному активному проекту, получает автора из контекста и сохраняет текст и серверное время. Добавление комментария оставляет поля и версию задачи прежними. Чтение обсуждения выполняется запросом по `task_id` |

Отдельный агрегат комментария — проектное решение. Добавление записи не требует загрузки истории и не вступает в конфликт с редактированием полей задачи. При появлении операций удаления задачи, смены состава или архивации во время записи потребуется явно определить транзакционные границы и судьбу комментариев.

## Правила между агрегатами

- **Доступ.** Для чтения и записи проверять членство текущего пользователя в проекте. Архив разрешает чтение, операции записи возвращают 409. Недоступный проект или задача возвращает 404.
- **Назначение.** Исполнитель может отсутствовать или быть участником проекта задачи. Внешний ключ SQLite проверяет существование пользователя, принадлежность именно проекту проверяет прикладная операция.
- **Добавление комментария.** Связь с задачей и автором фиксируется при вставке. Отдельная операция возвращает 201 и созданную запись. Проверки доступа и архива предшествуют записи.
- **Редактирование задачи.** Конфликт версии возвращает 409. Сервер не сохраняет изменения по устаревшей версии.

## Модели чтения

`TaskDetail` объединяет задачу с комментариями и отображаемыми именами авторов. `AttentionOverview` вычисляется для текущего руководителя по его активным проектам с учётом членства. Причины выводятся из статуса, срока, назначения и активной отметки комментария. Отметка включает также завершённую задачу. Запись об обзоре в SQLite не создаётся.
