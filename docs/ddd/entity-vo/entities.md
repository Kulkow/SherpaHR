# Сущности

Идентичность сущности определяется её ключом и сохраняется при изменении полей. Имена полей в таблице соответствуют существующей схеме SQLite.

| Сущность | Идентичность и поля | Поведение и жизненный цикл |
|---|---|---|
| Пользователь (`User`) | `id`, `name` | Участвует в проектах, может быть руководителем, исполнителем или автором комментария. В демо создаётся при инициализации. Операций создания и редактирования через API нет |
| Проект (`Project`) | `id`, `name`, `description`, `owner_id`, `archived` | Определяет область членства и доступность записи. У каждого проекта один руководитель. В демо проект и его архивный статус задаются при инициализации |
| Участник проекта (`ProjectMember`) | Составной ключ `(project_id, user_id)` | Связующая сущность внутри проекта. Подтверждает членство конкретного пользователя. Пара уникальна. API читает состав, а изменение состава остаётся за рамками v7 |
| Задача (`Task`) | `id`, `project_id`, `title`, `description`, `status`, `assignee_id`, `due_at`, `updated_at`, `version` | Создаётся в активном проекте. Проект задачи фиксирован для существующих операций. Участник может менять название, описание, статус, исполнителя и срок. Сохранение обновляет время и увеличивает версию. Доступные переходы определяет текущая матрица `TaskStatus` |
| Комментарий (`Comment`) | `id`, `task_id`, `user_id`, `body`, `created_at` | Запись обсуждения одной задачи. При добавлении автор определяется выбранным пользователем, время задаёт сервер. Комментарий доступен при чтении карточки. Редактирование и удаление не предусмотрены |

Руководитель, исполнитель и автор — роли пользователя в конкретной связи. Архивность и статус — свойства сущностей. `author`, `task_count`, списки участников и комментариев в JSON собираются для чтения. `metadata` хранит служебные `schema_version` и `seeded_at`.

Источники: [схема SQLite](../../../backend/schema.sql), [API](../../api.md), [инициализация демо](../../../backend/src/Database.php).
