# Репозитории агрегатов

Названия операций и сигнатуры предложены для v7. Результаты записи содержат сохранённые значения, включая присвоенные БД идентификаторы. `null` на чтении означает отсутствие записи, а ошибка доступа определяется прикладной операцией или специально ограниченным запросом.

| Репозиторий и таблицы | Операции | Назначение |
|---|---|---|
| `UserRepository` · `users` | `find(UserId): User?` | Проверить существование выбранного демо-пользователя и прочитать его профиль. Создание каталога относится к инициализации демо |
| `ProjectRepository` · `projects`, `project_members` | `find(ProjectId): Project?`, `hasMember(ProjectId, UserId): bool` | Прочитать проект, включая архивность и руководителя, проверить членство по составному ключу. Членство принадлежит агрегату проекта и читается без загрузки всех участников |
| `TaskRepository` · `tasks` | `find(TaskId): Task?`, `insert(NewTask): Task`, `update(Task, TaskVersion expectedVersion): Task` | Прочитать задачу для прикладной операции, создать с начальной версией, сохранить по ожидаемой версии и вернуть обновлённые поля. При несовпадении версии сообщить о конфликте |
| `CommentRepository` · `comments` | `insert(NewComment): Comment` | Записать комментарий с идентификаторами задачи и автора и серверным временем. Чтение обсуждения выполняет запрос карточки |

`NewTask` содержит проект, название, описание, статус, исполнителя, срок и время обновления. `NewComment` содержит задачу, автора, текст и время создания. Эти данные формируются после проверки входа и доступа. При частичной правке поля объединяются с текущей задачей, поэтому репозиторий получает итоговое состояние и ожидаемую версию. Значения из запроса передаются SQL через параметры PDO.

PDO-строки преобразуются в типизированные данные с явными столбцами. Ошибку SQLite, конфликт версии и отсутствие строки стоит различать: HTTP-обработчик переводит результат прикладной операции в статус и JSON. Изменение состава, архивирование и удаление агрегатов в v7 не предусмотрены.
