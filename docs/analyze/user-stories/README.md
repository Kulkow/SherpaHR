После повторного открытия комментарий виден с автором и временем. Пустой текст, чужая задача и архив отклоняются. Отправка сохраняет несохранённые поля задачи в открытой форме | Не реализовано, [UC-06](../use-cases/README.md) |

Чужие и архивные проекты исключены. Для каждой строки видны проект и причина отбора. При отсутствии таких задач показано пустое состояние | Не реализовано, [UC-07](../use-cases/README.md) |

Сохраняются существующие проверки доступа и записи. Результат изменения отражается в обзоре при его обновлении | Частично, карточка и изменение задачи существуют. Переход из обзора и ответ недоступны, [UC-03, UC-05–UC-07](../use-cases/README.md) |

## Предлагаемое правило для US-05

Для демо считать проект координируемым, если пользователь указан в `owner_id`, состоит в проекте и проект активен. Для Анны это проекты №1, №2 и №3. Если координаторами станут участники без роли владельца, понадобится отдельное правило определения их проектов.

Предлагаемые сигналы: статус `blocked`, истёкший срок у задачи со статусом, отличным от `done`, и отсутствие исполнителя у незавершённой задачи. Задачу с несколькими сигналами показывать одной строкой со всеми причинами. Например, №5 при фиксированной дате инициализации `2026-11-11T08:00:00Z` одновременно заблокирована и просрочена, а №7 попадает в обзор по отсутствию исполнителя. Текст обсуждения остаётся доступен в карточке. Препятствие, описанное только в тексте задачи с назначенным исполнителем и без других сигналов, правило пропустит.
