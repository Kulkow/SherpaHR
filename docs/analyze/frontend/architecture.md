# Архитектура, состояние и интерфейс

| ID | Приоритет | Проблема и последствия | Предлагаемое изменение |
|---|---|---|---|
| A-01 | v7 | **Завершение записи может пересечься с повторной загрузкой проекта.** Сохранение проверяет ID пользователя и проекта, но не поколение загрузки списка. Если пользователь снова выберет тот же проект во время создания, GET может уже содержать новую задачу, а завершение POST добавит её второй раз. При другом порядке ответов загрузка может затереть обновлённый список. Боковой список остаётся активным во время записи. Риск следует из порядка операций, браузерным тестом не подтверждён. [app.ts, загрузка проекта](../../../frontend/src/app.ts#L69-L86), [сохранение](../../../frontend/src/app.ts#L127-L156), [навигация](../../../frontend/src/app.html#L10-L17) | Согласовать обновление с конкретной загрузкой. После успешной записи перечитать список или применять идемпотентное обновление по ID и защищать его от старого ответа загрузки |
| A-02 | v7 | **Обработка HTTP и ошибок JSON смешана.** `response.json()` выполняется до проверки статуса. Ответ прокси без JSON выдаст ошибку разбора, из которой пользователь не узнает HTTP-статус. У запросов нет возможности отмены, а общий флаг `saving` держит формы заблокированными и после ухода из проекта до завершения исходного запроса. [api.ts](https://github.com/SherpaRPA/SherpaHR/blob/d85eb5e76bd0c839798ec55d21c7f0745b6f995f/frontend/src/api.ts#L7-L15), [app.ts](../../../frontend/src/app.ts#L127-L173) | Сохранять статус и контекст при разборе ошибки. Отменять устаревшие запросы чтения, а состояние записи привязывать к конкретной операции. Учитывать, что отмена ожидания клиентом не гарантирует отмену записи на сервере |
| A-03 | v7 | **Ошибка загрузки проекта выглядит как пустая таблица.** Ошибка появляется в общем баннере, а пустая таблица сообщает об отсутствии задач. Кнопка повторной загрузки доступна только при отсутствии выбранного проекта. При открытии карточки отдельного состояния ожидания тоже нет. [app.ts](../../../frontend/src/app.ts#L69-L111), [app.html](../../../frontend/src/app.html#L20-L49) | Добавить отдельные состояния загрузки, ошибки, пустого результата и успеха для списка и карточки. Дать повторить конкретный запрос |
| A-04 | v7 | **Компонент объединяет навигацию, запросы, состояние и формы.** Выбранный проект одновременно хранится отдельным объектом и в массиве: после создания счётчик обновляется только в массиве. Карточка берёт участников, архив и путь сохранения из текущего проекта, что важно при открытии задачи из общего обзора. [app.ts](../../../frontend/src/app.ts#L14-L35), [сохранение](../../../frontend/src/app.ts#L127-L152), [форма](../../../frontend/src/app.html#L48-L65) | Хранить один список проектов и выбранный ID. Передавать карточке явный контекст проекта задачи и выделить её как повторно используемую часть при реализации обзора |
| A-05 | Доступность | **Фокус не переводится в карточку.** В мобильном режиме карточка появляется под списком. После открытия фокус остаётся на кнопке задачи, а по закрытии находившийся в карточке элемент исчезает без явного восстановления фокуса. [app.ts](../../../frontend/src/app.ts#L94-L119), [app.html](../../../frontend/src/app.html#L37-L50), [мобильный режим](../../../frontend/src/styles.css#L432-L455) | После открытия переводить фокус на заголовок или первый подходящий элемент и при закрытии возвращать к кнопке, которая открыла карточку |
| A-06 | Доступность | **Низкий контраст мелкого текста.** Метка номера задачи `#87939b` на белом фоне даёт около 3,15:1, примечание `#919ba3` на `#f6f8fa` около 2,66:1. Значения ниже ориентира 4,5:1 для мелкого текста. [фон](../../../frontend/src/styles.css#L1-L7), [белый фон таблицы](../../../frontend/src/styles.css#L198-L203), [цвета текста](../../../frontend/src/styles.css#L273-L300) | Подобрать более тёмные оттенки и проверить контраст на фактических фонах |
| A-07 | При росте списка | **Фильтрация выполняется из шаблона.** При проверке представления создаётся новый массив, поисковая строка приводится к нижнему регистру для каждой подходящей по статусу задачи, а поиск имени сканирует каталог для каждой строки. На демо это небольшой объём. [app.ts](../../../frontend/src/app.ts#L89-L92), [поиск имени](../../../frontend/src/app.ts#L176-L177), [таблица](../../../frontend/src/app.html#L36-L39) | При росте перевести фильтры на сигналы и вычисляемое значение, нормализовать запрос один раз и использовать индекс имён по ID |
| A-08 | Проверки | **Нет frontend-регрессий в текущем наборе скриптов.** TypeScript и сборка проверяют компиляцию, а HTTP smoke-тест покрывает сервер. Сценарии переключения проекта во время сохранения, повторной загрузки и сохранения черновика требуют отдельной проверки. [package.json](../../../frontend/package.json), [smoke.php](../../../backend/tests/smoke.php) | Для v7 зафиксировать ручные сценарии и добавить целевые проверки там, где меняется управление асинхронным состоянием |
