# Синтаксис, читаемость и именование

| ID | Наблюдение и последствия | Предлагаемое изменение |
|---|---|---|
| R-01 | **Совместимость.** В PHP 8.5 локальная переменная `$http_response_header` вызывает предупреждение deprecation. Тест дополнительно предполагает, что заголовок есть и регулярное выражение нашло статус. При транспортной ошибке это затрудняет диагностику первопричины. [smoke.php, строки 31–43](../../../backend/tests/smoke.php#L31-L43) | При поддержке PHP 8.4 и 8.5 читать заголовки через `http_get_last_response_headers()`. Проверять получение ответа и строки статуса до разбора JSON |
| R-02 | **Читаемость SQL.** Запросы и списки позиционных параметров записаны длинными строками. Связь между столбцами SQL и элементами массива приходится проверять по порядку. [Application.php, строки 61–97](https://github.com/SherpaRPA/SherpaHR/blob/d85eb5e76bd0c839798ec55d21c7f0745b6f995f/backend/src/Application.php#L61-L97) | Отформатировать сложные запросы на несколько строк. Для длинных INSERT и UPDATE использовать именованные параметры |
| R-03 | **Именование.** `project()` и `task()` скрывают проверку членства и исключение 404. Из имени `writable()` можно ожидать логический результат, хотя метод возвращает `void` и выбрасывает ошибку. [Application.php, строки 182–205](https://github.com/SherpaRPA/SherpaHR/blob/d85eb5e76bd0c839798ec55d21c7f0745b6f995f/backend/src/Application.php#L182-L205) | Названия вроде `requireAccessibleProject()`, `requireAccessibleTask()` и `assertProjectIsWritable()` отражают контракт |
| R-04 | **Неявные поля и числа.** В демо-данных `$row[6]` и `$row[7]` обозначают срок и время обновления. Заполнение проектов и пользователей зависит от порядка столбцов таблиц. [Database.php, строки 40–88](../../../backend/src/Database.php#L40-L88) | Указать столбцы во всех INSERT. Дать смещениям имена через ассоциативные данные или явное распаковывание |
| R-05 | **Мутация по ссылке.** После `foreach ($projects as &$project)` переменная остаётся ссылкой на последний элемент до выхода из области видимости. Текущий метод сразу возвращается, поэтому наблюдаемой порчи данных здесь нет. [Application.php, строки 52–59](https://github.com/SherpaRPA/SherpaHR/blob/d85eb5e76bd0c839798ec55d21c7f0745b6f995f/backend/src/Application.php#L52-L59) | Обогатить строки без ссылки или явно снять ссылку после цикла |
| R-06 | **Читаемость границ.** Лимиты тела и полей записаны числовыми литералами, а имена `$data`, `$out`, `$max` не показывают, какое преобразование происходит и в чём измеряется предел. [Application.php, строки 111–179](https://github.com/SherpaRPA/SherpaHR/blob/d85eb5e76bd0c839798ec55d21c7f0745b6f995f/backend/src/Application.php#L111-L179) | Использовать `$payload`, `$validatedFields` и `$maxBytes`. Именовать пределы полей и тела там, где это помогает сопоставить валидацию с контрактом API |
