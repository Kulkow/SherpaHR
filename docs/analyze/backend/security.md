# Безопасность

## Модель доступа

`X-Demo-User` задаёт выбранного пользователя, а отсутствие заголовка выбирает Анну. Сервер проверяет существование ID и затем членство от имени выбранного пользователя. Это предусмотрено для локального демо. Compose публикует порт на loopback. Если API станет доступен недоверенным клиентам, эта модель позволит читать и изменять данные с правами любого демо-пользователя. Для такого развёртывания нужна серверная проверка личности с получением ID из доверенного контекста. [Application.php, строки 18–30](https://github.com/SherpaRPA/SherpaHR/blob/d85eb5e76bd0c839798ec55d21c7f0745b6f995f/backend/src/Application.php#L18-L30), [проверки доступа](https://github.com/SherpaRPA/SherpaHR/blob/d85eb5e76bd0c839798ec55d21c7f0745b6f995f/backend/src/Application.php#L182-L205), [Compose](../../../compose.yaml), [контракт API](../../api.md).

## Риски и границы проверки

| ID | Наблюдение и условия | Меры |
|---|---|---|
| S-01 | **Выдача общего каталога пользователей.** `GET /api/context` возвращает всех пользователей вне зависимости от общего членства. Это нужно для демо-переключателя. В рабочей системе может раскрывать имена пользователей вне доступных проектов. [Application.php, строки 43–49](https://github.com/SherpaRPA/SherpaHR/blob/d85eb5e76bd0c839798ec55d21c7f0745b6f995f/backend/src/Application.php#L43-L49) | При появлении реальных учётных записей вернуть профиль текущего пользователя. Участников отдавать в пределах проекта |
| S-02 | **Неограниченные выборки.** API загружает все задачи проекта и всю переписку карточки сразу. При росте базы большой ответ увеличивает время и память на SQL, создание PHP-массивов и JSON. Лимит тела записи размер ответа не ограничивает. Оценка основана на коде, без замера нагрузки. [Application.php, строки 61–81](https://github.com/SherpaRPA/SherpaHR/blob/d85eb5e76bd0c839798ec55d21c7f0745b6f995f/backend/src/Application.php#L61-L81), [лимит тела](https://github.com/SherpaRPA/SherpaHR/blob/d85eb5e76bd0c839798ec55d21c7f0745b6f995f/backend/src/Application.php#L162-L179) | При росте данных добавить серверную пагинацию и разумные максимумы страниц. Полная история остаётся доступной через последовательную подгрузку |
| S-03 | **Ошибка подключения вне JSON-обработчика.** Сбой чтения схемы, открытия БД или инициализации происходит до входа в `Application::run()`. Клиент может получить ответ вне формата API. Если в окружении включён показ ошибок, детали сбоя могут попасть в ответ. [router.php, строки 4–9](../../../backend/router.php#L4-L9), [Application.php, строки 12–38](https://github.com/SherpaRPA/SherpaHR/blob/d85eb5e76bd0c839798ec55d21c7f0745b6f995f/backend/src/Application.php#L12-L38) | Обрабатывать ошибки на общем уровне для API, логировать детали на сервере, клиенту отдавать стабильный JSON 500 |
| S-04 | **Проверка прав отдельно от записи.** API проверяет членство и архив перед INSERT или UPDATE. При появлении конкурентных изменений состава и архива условия могут измениться между чтением и записью. Сейчас проектами и участниками через API управлять нельзя, поэтому это риск расширения. [Application.php, строки 61–97](https://github.com/SherpaRPA/SherpaHR/blob/d85eb5e76bd0c839798ec55d21c7f0745b6f995f/backend/src/Application.php#L61-L97) | При добавлении управления доступом связать проверку и запись транзакцией или условием записи в SQL |

По проверенным участкам данные из запросов передаются в SQL через параметры PDO. Прямое чтение проекта и карточки ограничено членством. Маршрутизатор проверяет канонический путь файла перед статической выдачей. В Angular текст комментария выводится интерполяцией. Хранение произвольного текста в JSON само по себе не подтверждает XSS.
