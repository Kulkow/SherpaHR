# Архитектура

| ID | Приоритет | Проблема и последствия | Предлагаемое изменение |
|---|---|---|---|
| A-01 | v7 | **Добавление комментариев обрывается в маршруте.** Вход и доступ проверяются, затем API возвращает 501. Smoke-тест требует сохранения, 201 и последующего чтения. [Application.php](https://github.com/SherpaRPA/SherpaHR/blob/d85eb5e76bd0c839798ec55d21c7f0745b6f995f/backend/src/Application.php#L101-L107), [smoke.php](../../../backend/tests/smoke.php#L106-L111) | Добавить операцию записи комментария с автором и временем, вернуть созданную запись в форме, которую читает карточка |
| A-02 | v7 | **Список и карточка читают разные множества задач.** Внутреннее соединение списка по исполнителю исключает `NULL`. Карточка и счётчик включают такие задачи. [Application.php](https://github.com/SherpaRPA/SherpaHR/blob/d85eb5e76bd0c839798ec55d21c7f0745b6f995f/backend/src/Application.php#L52-L65), [чтение карточки](https://github.com/SherpaRPA/SherpaHR/blob/d85eb5e76bd0c839798ec55d21c7f0745b6f995f/backend/src/Application.php#L191-L198) | Убрать лишнее соединение. Добавить регрессионную проверку списка и согласованности счётчика для задачи без исполнителя |
| A-03 | Развитие | **Инициализация берёт блокировку записи при каждом API-запросе.** `connect()` вызывает `initialize()`, которая выполняет `BEGIN IMMEDIATE` до проверки версии. Это происходит и для чтения, и для healthcheck. На нескольких процессах возможны лишние ожидания при активном писателе. [Database.php](../../../backend/src/Database.php#L6-L37), [router.php](../../../backend/router.php#L4-L9), [Compose](../../../compose.yaml) | Один раз запускать инициализацию при старте. Если она остаётся ленивой, читать версию без блокировки записи и повторно проверять под блокировкой только при необходимости изменений |
| A-04 | При изменении схемы | **Есть метка версии без миграций.** Любое непустое значение `schema_version` останавливает инициализацию. Новый SQL не обновит существующий volume. [Database.php](../../../backend/src/Database.php#L21-L37), [запись версии](../../../backend/src/Database.php#L90-L92) | При первом изменении схемы ввести последовательные миграции от известных версий. Проверить обновление существующей БД и новую установку |
| A-05 | Развитие | **Маршруты смешаны с правами, SQL, валидацией и сериализацией.** `dispatch()` приходится читать целиком, чтобы проверить порядок проверок и контракт записи. Путь запроса разбирается дважды. Префикс `/api` совпадает и с путями вроде `/apiculture`. [Application.php](https://github.com/SherpaRPA/SherpaHR/blob/d85eb5e76bd0c839798ec55d21c7f0745b6f995f/backend/src/Application.php#L18-L108), [router.php](../../../backend/router.php#L4-L9) | Уточнить границу `/api` и разбивать растущие сценарии на небольшие обработчики. Оставить единое место для обработки ошибок API, включая подключение к БД |
| A-06 | При конкурентных записях | **Ответ PATCH читается отдельным запросом после UPDATE.** Условие по `version` защищает от перезаписи устаревшей версией. При нескольких рабочих процессах успешный PATCH может вернуть уже более новую строку, если другой PATCH успел записать между UPDATE и SELECT. [Application.php](https://github.com/SherpaRPA/SherpaHR/blob/d85eb5e76bd0c839798ec55d21c7f0745b6f995f/backend/src/Application.php#L84-L98) | Возвращать изменённую строку из самой операции записи, например через SQLite `RETURNING`, либо читать её в той же транзакции |
| A-07 | При росте базы | **Список проектов делает отдельный запрос участников на каждый проект.** Для N проектов выполняется N дополнительных выборок. Первичная выборка использует `user_id`, который стоит вторым в составном ключе членства. Замеров на большой базе нет. [Application.php](https://github.com/SherpaRPA/SherpaHR/blob/d85eb5e76bd0c839798ec55d21c7f0745b6f995f/backend/src/Application.php#L52-L59), [schema.sql](../../../backend/schema.sql#L6-L9) | При измеримом росте получать участников одним запросом по набору проектов. Перед добавлением индекса с ведущим `user_id` проверить план выборки |
| A-08 | Надёжность проверок | **Тестовый порт резервируется и освобождается до запуска сервера.** Между закрытием сокета и стартом процесса порт может занять другой процесс. Сбои подготовки происходят до блока `finally`, который чистит временные файлы. [smoke.php](../../../backend/tests/smoke.php#L9-L27), [очистка](../../../backend/tests/smoke.php#L117-L126) | Повторять старт при конфликте порта и распространить очистку на этап подготовки |
