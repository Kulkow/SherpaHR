# Типизация входов и выходов

Во всех PHP-файлах включён `strict_types`. Для полей запроса уже есть проверки строк, целых чисел, допустимых статусов и дат UTC. Состав ассоциативных массивов и JSON-ответов при этом остаётся неявным.

| ID | Граница | Проблема | Предлагаемое изменение |
|---|---|---|---|
| T-01 | Вход задачи | У `description` и `status` оператор `??` объединяет отсутствующее поле и явный `null`. В PATCH отсутствие поля сохраняет значение, а явный `null` сбрасывает описание в пустую строку или статус в `open`. Для `due_at` и `assignee_id` очистка через `null` соответствует контракту. [Application.php, строки 111–151](https://github.com/SherpaRPA/SherpaHR/blob/d85eb5e76bd0c839798ec55d21c7f0745b6f995f/backend/src/Application.php#L111-L151), [справка API](../../api.md) | Применять значения по умолчанию только к отсутствующим полям POST. Для PATCH отдельно проверять присутствие и допустимость `null` |
| T-02 | Вход обновления | `version` входит в общий список полей, поэтому POST принимает и игнорирует его независимо от типа. PATCH с одной актуальной версией обновляет `updated_at` и увеличивает версию без изменения полей задачи. [Application.php, строки 67–97](https://github.com/SherpaRPA/SherpaHR/blob/d85eb5e76bd0c839798ec55d21c7f0745b6f995f/backend/src/Application.php#L67-L97), [список полей](https://github.com/SherpaRPA/SherpaHR/blob/d85eb5e76bd0c839798ec55d21c7f0745b6f995f/backend/src/Application.php#L111-L117) | Описать раздельные контракты создания и правки. Для пустой правки явно определить ответ и поведение версии |
| T-03 | Типы аргументов и результатов | Сигнатуры `array` у валидатора, методов загрузки и проверки проекта скрывают обязательные ключи, допустимые значения и разницу между списком и одной записью. Флаг `$partial` меняет форму результата без отражения в типе. [Application.php, строки 111–151](https://github.com/SherpaRPA/SherpaHR/blob/d85eb5e76bd0c839798ec55d21c7f0745b6f995f/backend/src/Application.php#L111-L151), [доступ к данным](https://github.com/SherpaRPA/SherpaHR/blob/d85eb5e76bd0c839798ec55d21c7f0745b6f995f/backend/src/Application.php#L182-L219) | Описать формы массивов PHPDoc для статического анализа. Разделить структуры создания, частичного обновления и результата чтения |
| T-04 | JSON-ответ | `SELECT *` и `respond(mixed ...)` связывают внешний контракт с колонками и результатом PDO. `archived` явно нормализуется в bool только для списка проектов. При отсутствии `seeded_at` запрос `fetchColumn()` может дать `false` вместо строки времени. При штатной инициализации метаданные создаются. [Application.php, строки 43–58](https://github.com/SherpaRPA/SherpaHR/blob/d85eb5e76bd0c839798ec55d21c7f0745b6f995f/backend/src/Application.php#L43-L58), [формирование ответа](https://github.com/SherpaRPA/SherpaHR/blob/d85eb5e76bd0c839798ec55d21c7f0745b6f995f/backend/src/Application.php#L221-L225), [Database.php](../../../backend/src/Database.php#L90-L92) | Собирать ответы из явно выбранных полей. Для отсутствующих обязательных метаданных определить серверную ошибку и структурированный ответ |
| T-05 | Граница чтения HTTP | `file_get_contents()` может вернуть `false`, а код сразу передаёт его в `strlen()`. Ожидается строка; редкий сбой чтения тела превращается в общую ошибку 500 через `Throwable`. [Application.php, строки 162–179](https://github.com/SherpaRPA/SherpaHR/blob/d85eb5e76bd0c839798ec55d21c7f0745b6f995f/backend/src/Application.php#L162-L179) | Отдельно проверять успешность чтения тела перед проверкой длины и декодированием |
