# API существующего приложения

Ответ: `{"data": ...}`; ошибка: `{"error": "описание"}` с соответствующим
HTTP-статусом. JSON UTF-8. Заголовок `X-Demo-User: 1` выбирает Анну,
`2` — Бориса, `3` — Веру. По умолчанию 1. Это открытый демо-переключатель,
не доказательство личности; локальный API не предназначен для публикации в сеть.

| Метод и путь | Поведение |
|---|---|
| `GET /api/health` | Проверка запуска сервиса |
| `GET /api/context` | Демо-пользователи, выбранный пользователь, время UTC и дата создания демо |
| `GET /api/attention` | Обзор задач активных проектов текущего руководителя |
| `GET /api/projects` | Только проекты текущего пользователя, участники и количество задач |
| `GET /api/projects/{id}/tasks` | Все задачи доступного проекта, включая задачи без исполнителя |
| `POST /api/projects/{id}/tasks` | Создать задачу в активном проекте |
| `GET /api/tasks/{id}` | Доступная задача с комментариями и авторами |
| `PATCH /api/tasks/{id}` | Изменить поля с проверкой версии |
| `POST /api/tasks/{id}/comments` | Сохранить комментарий в активном проекте и вернуть созданную запись с HTTP 201 |
| `POST /api/tasks/{id}/comments/{commentId}/resolve` | Текущий руководитель обрабатывает отметку и получает `{"data":{"attention":"resolved"}}` |

Поля задачи для создания и изменения: `title`, `description`, `status`,
`assignee_id`, `due_at`. При создании `title` обязателен. Новая задача всегда получает статус `open`.
При явной передаче `status` допустимо только значение `open`. Неизвестные поля
отклоняются. Исполнитель — участник проекта или `null`. Даты — строго
`YYYY-MM-DDTHH:mm:ssZ` либо `null`; текущий UI редактирует их с точностью до минуты.
Для PATCH обязательно целое поле `version`, полученное при чтении.
Успешное изменение увеличивает версию. Устаревшая версия возвращает 409.
Смена статуса проверяется по [матрице переходов](ddd/entity-vo/value-objects.md#переходы-taskstatus).
Запрещённый переход возвращает 422 и не меняет задачу.
Карточка и ответы записи задачи содержат `allowed_statuses` с допустимыми целевыми статусами.
Отсутствующие поля PATCH сохраняют прежние значения. Явный `null` очищает
исполнителя или срок, а для названия, описания и статуса возвращает 422.
Метод добавления комментария принимает `{"body":"текст"}`. Сервер определяет
автора по выбранному пользователю и время по UTC. Ответ содержит `id`, `task_id`,
`user_id`, `body`, `created_at` и `author`. Комментарий доступен через карточку
задачи и не увеличивает её версию. Необязательный флаг
`requires_attention: true` помечает его для текущего руководителя проекта.
Поле `attention` в ответах принимает `none`, `requested` или `resolved`.
Участник без роли руководителя получает 403 при попытке обработать отметку.

Обзор возвращает задачу один раз, со всеми подходящими причинами. Активная отметка
добавляет `comment_attention` даже для завершённой задачи. Для незавершённых
задач учитываются `blocked`, `overdue` и `unassigned`. Приоритет определяется
первой причиной в этом порядке: `comment_attention`, `blocked`, `overdue`, `unassigned`.
Внутри приоритета задачи сортируются по сроку с пустыми значениями в конце, затем по ID.

Машиночитаемый контракт и источник типов TypeScript — [OpenAPI](../contracts/openapi.yaml).

Максимумы строк в байтах UTF-8: название 200, описание 10000, комментарий 5000.
Максимум тела изменения — 32 KiB. Ошибка валидации — 422, JSON — 400,
неизвестный пользователь — 401, отсутствующий или недоступный объект — 404,
запись в архив — 409. Поиск и фильтр статуса в текущем UI выполняются локально.
