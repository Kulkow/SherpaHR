# Docker и проверки

Один сервис Compose отдаёт собранный Angular и PHP API с одного origin. Порт опубликован на loopback, SQLite хранится в именованном volume. При открытии файла версии 1 бэкенд добавляет колонку отметки внимания в транзакции. Существующие комментарии получают состояние `none`. Обычные запросы к базе версии 2 обходятся без блокировки записи для инициализации.

Запуск приложения — `docker compose up --build -d --wait`. Проверки выполняются в Docker на PHP 8.4 и Node версии из Dockerfile. [Compose](../../compose.yaml), [Dockerfile](../../Dockerfile).

| Команда | Проверки |
|---|---|
| `make check-php` | PHPUnit и PHPStan level 9 |
| `make check-frontend` | Актуальность типов OpenAPI, ESLint для TypeScript и Angular-шаблонов, TypeScript, тесты Node и Angular-сборка |
| `make check` | PHP, frontend и HTTP smoke на временной SQLite |
| `make e2e` | Playwright в браузере против собранного приложения в изолированном Compose-проекте |

Хук [pre-commit](../../.githooks/pre-commit) запускает `make check`. Его можно подключить командой `git config core.hooksPath .githooks`. Хук проверяет рабочее дерево, включая локальные правки вне индекса.

## Браузерный сценарий

Борис отправляет отмеченный комментарий к завершённой задаче. Анна видит её в обзоре, открывает карточку и обрабатывает отметку. Задача исчезает из обзора. Отдельное действие в том же сценарии проверяет доступные статусы и сохранение изменения.

E2E поднимает изолированный Compose-проект и SQLite-volume без публикации порта. Браузер использует сетевое пространство тестового приложения и обращается к нему по loopback. Данные удаляются при выходе. Playwright сохраняет трассировку при неудаче в `frontend/test-results`. [Конфигурация E2E](../../compose.e2e.yaml), [сценарий](../../frontend/e2e/attention.spec.ts).
