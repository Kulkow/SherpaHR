# Предметная область и контракты

## Единый язык

Используем термины предметной области в интерфейсе, документации, названиях операций API и тестах. В русском тексте используем названия из левой колонки, в коде и контракте — согласованные имена из средней.

| Термин | Имя в коде или API | Значение в Project Desk |
|---|---|---|
| Проект | `Project` | Группа участников, задач и обсуждений задач |
| Руководитель проекта | `owner_id` | Пользователь, отвечающий за проект. Доступ определяется членством |
| Участник проекта | `ProjectMember` | Пользователь с доступом к проекту. В активном проекте может менять задачи |
| Задача | `Task` | Работа внутри проекта. Может иметь исполнителя и срок |
| Исполнитель | `assignee_id` | Участник проекта, которому назначена задача. При отсутствии назначения значение `null` |
| Архивный проект | `archived` | История доступна участникам для чтения. Запись отклоняется |
| Комментарий | `Comment` | Запись обсуждения задачи с автором и временем создания UTC |
| Обзор «Требуют внимания» | `AttentionOverview` | Вычисляемый список задач активных проектов руководителя |
| Причина внимания | `AttentionReason` | Признак отбора задачи. У одной задачи может быть несколько причин |

Статусы задачи сохраняют канонические значения `open`, `in_progress`, `blocked` и `done`. «Просрочена» и «Без исполнителя» вычисляются из данных задачи. Для первой версии обзора берём правила из [плана v7](../tasks/task-v7-implementation-plan.md), включая область проектов, сравнение срока с серверным временем UTC и порядок причин. Текст переписки остаётся в карточке.

## Общий HTTP-контракт

Источник структуры HTTP API — [contracts/openapi.yaml](../../contracts/openapi.yaml). В нём описываются маршруты, обязательные и допускающие `null` поля, статусы, формы успешных ответов и ошибок. Словарь определяет смысл терминов, OpenAPI определяет формат обмена. [Текущая справка API](../api.md) служит основой для переноса.

- Backend проверяет входящие данные и явно формирует JSON. Сохраняются конверты `{"data": ...}` и `{"error": "..."}`. PHP-типы записи SQLite остаются внутри backend.
- Frontend получает TypeScript-типы из той же спецификации через `@hey-api/openapi-ts`. Генерируемый файл обновляется вместе со спецификацией. Проверка регенерирует типы и сверяет их с версией в рабочем дереве. HTTP-клиент проверяет конверт и обрабатывает ответы вне JSON, поскольку сгенерированные типы действуют при компиляции.
- Для PATCH отдельно описываются отсутствующее поле и явный `null`. `null` очищает срок или исполнителя. `version` обязателен, конфликт возвращает 409. Даты передаются с секундами в UTC.
- Новый комментарий возвращает 201 и объект той же структуры, что и в обсуждении карточки. Для обзора добавить отдельную операцию чтения с причинами и данными, необходимыми для перехода в карточку.
- Менять контракт, PHP-реализацию, сгенерированные типы, документацию и проверки одним изменением. Сохранять поведение существующих клиентов при добавлении маршрутов и полей.
